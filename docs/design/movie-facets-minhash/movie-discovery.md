# 电影发现：Faceted Semantic Search

状态：场景和核心能力已确认；当前页面为概念草图，尚未实现。

![电影发现界面](assets/movie-discovery-v1.png)

## 用户场景

用户用自然语言描述想看的故事或观影感受，例如：

> A lighthearted adventure with ordinary people

语义检索根据影片简介找到相关候选，用户再按主类型、年代或国家／地区浏览这些候选，并通过时长等条件继续缩小范围。这个 Demo 的重点是把相关结果组织成可比较、可继续探索的分组。

## 页面与交互草案

| 区域 | 设计 |
| --- | --- |
| 顶栏 | Milvus 3.0 标识、`Movie Discovery with Search Aggregation` 标题和 Source 链接 |
| 查询区 | 自然语言输入、预设查询下拉框和 Search 按钮 |
| 浏览工具栏 | `Group by` 在 `Genre`、`Decade`、`Region` 间切换；示例筛选条件为 `Under 120 min` |
| 视图切换 | `Grouped` 为主视图，`List` 用于对照普通语义搜索结果 |
| 分组内容 | 每组显示少量代表影片，包含原创海报、片名、年份、时长和一句简介 |
| 继续探索 | 点击 `Explore this genre` 后，以相应字段值作为过滤条件重新检索 |

草图中的三个分组为 Adventure、Comedy 和 Animation，每组显示两部虚构电影。分组数量、每组保留候选数和默认筛选条件都可以在实现阶段调整。

切换分组维度或筛选条件应触发对应的服务端查询。普通列表和分组视图分别请求普通搜索与 Search Aggregation，不把前端对一份固定 Top-K 结果的重新排版当作服务端聚合。

## 数据设置

允许使用原创虚构片库，以降低真实影视素材的授权负担。当前草图中的片名、简介和海报都是虚构设计素材，页面需要保留清楚的合成数据说明。若后续采用真实影片，需另行确认基础数据、剧情文本和图片的使用及再分发许可。

候选字段如下，最终 Schema 在实现时确定：

| 字段 | 用途 |
| --- | --- |
| `movie_id` | 稳定主键 |
| `title`、`synopsis` | 展示与语义检索内容 |
| `synopsis_embedding` | 普通稠密向量，模型及维度待定 |
| `primary_genre` | 可直接用于分组的单值主类型 |
| `release_year`、`decade` | 展示年份与按年代分组 |
| `region` | 单值国家／地区分组字段 |
| `runtime_minutes` | 时长展示和数值过滤 |
| `poster_path` | 随数据集提供的原创海报资源 |

首版不需要购票、播放、外部流媒体入口、用户账号或真实平台评分。数据规模和具体电影清单尚未确定；草图里的六部影片只是视觉示例。

## Milvus 能力与统计边界

主路径为查询文本生成向量、Milvus 执行 ANN 检索与 Search Aggregation、前端渲染返回的分组。可对分组配置代表性结果和候选范围内的统计值。

实现时遵守以下语义：

- Search Aggregation 的返回入口为 `result.agg_buckets`，启用聚合时普通搜索命中列表为空。
- `count` 和统计值来自检索阶段保留的候选，不是全库电影数，也不是所有语义相关影片的精确统计。
- 每个完整分组键的候选预算由聚合树中最大的 `TopHits.size` 决定；改变预算可能改变数量、统计值与分组顺序。
- 图中的 `2 candidates` 表示该组保留的候选数。页面底部保留“统计仅覆盖保留候选”的说明。
- 分组键应使用受支持的标量字段；首版用单值主类型和预先计算的年代字段，避免依赖数组类型的多标签分组。
- 当前设计不组合 Hybrid Search 与 Search Aggregation。需要扩展时重新核实目标版本的支持范围。

## 实现前待确认

需要选择文本 Embedding 模型、固定数据规模及预设查询，并确认各分组都有足够的相关候选以展示分组价值。候选数、相似度和可能增加的统计值都应来自真实请求；若数据不足，应明确显示实际返回数量。

电影素材的来源记录、许可说明和合成数据标识应随样本一同保存。文档与页面不应暗示虚构影片真实上映，或得到真实电影公司和演员的认可。
