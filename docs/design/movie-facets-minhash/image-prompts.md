Keep this family resemblance. Crisp practical readable UI, straight-on screenshot-like rendering, no device frame or browser chrome.

## MinHash near-duplicate detection

Use case: ui-mockup.
Asset type: a high-fidelity desktop web application frontend concept, ONE complete screen, landscape 16:9 at approximately 2048 x 1152. This is an interface design image for discussion, not a working webpage.
Primary request: design "Near-Duplicate Detection with MinHash", another member of an existing Milvus 3.0 technical-demo family. This screen demonstrates ONLY MinHash + LSH text near-duplicate detection. It does NOT include Embedding, ANN comparisons, clustering, LLM judgments or an explanation of the MinHash algorithm.
Existing design-family reference, reconstructed from actual frontend code: Inter/system sans-serif, light cool-gray canvas #f4f6f9, white panels, slate text #111827, gray #e5e7eb fine borders, 12–16 px rounded corners and restrained shadows, cyan #00b3ff Milvus wordmark with small outlined "3.0" badge, compact topbar, blue #1d4ed8 primary action. Teal/green for similar content and gentle amber for textual differences. Practical, polished technical demo rather than a generic SaaS dashboard; match a sibling movie search UI in the same light design family. Straight-on screenshot-like rendering, no browser chrome, no device frame.
Composition:
1. Compact topbar: small cyan "milvus" wordmark and outlined "3.0" badge, dark title "Near-Duplicate Detection with MinHash", GitHub icon plus "Source" at far right.
2. A compact pale-blue introduction strip: "Find copied and lightly edited documents." A small quiet badge "MinHash + LSH · No embedding model".
3. Main white toolbar: preset control "Example: Light edits" with dropdown chevron, short secondary button "Reset", and a strong blue "Detect duplicates" button. At the right show a restrained result label "2 candidates above threshold". Avoid large KPI cards.
4. Below, a substantial THREE-column workspace, clearly connected by matching selected-state colors but NO flowchart arrows. Approximate widths 36% / 27% / 37%.
LEFT PANEL, titled "Incoming document", secondary text "Paste or edit your text". An editable title line "A weekend by the river". A spacious textarea showing readable short paragraphs:
"On Sunday, we followed the river path to the old bridge. The morning market was already busy, so we bought bread and coffee before continuing."
"Beyond the bridge, a narrow trail led to a quiet garden. We spent the afternoon there and returned to town before sunset."
At the bottom of this panel a small "Detection threshold" control, value "0.85", a blue slider and understated help "Threshold applies to estimated Jaccard similarity." Clear paragraph spacing, no code syntax.
MIDDLE PANEL, titled "Retrieved candidates", tiny secondary "3 candidates". Three selectable result cards stacked vertically, first selected with pale blue fill and blue border. Each has a document icon, filename, short excerpt and a right-aligned score. Column label "Estimated Jaccard".
First selected card: "river-weekend-041.txt", score "0.94", green small badge "Above threshold", excerpt "On Saturday, we followed the river path…".
Second card: "riverside-guide-018.txt", score "0.87", green small badge "Above threshold", excerpt "The morning market was already busy…".
Third card: "city-walk-073.txt", score "0.43", muted badge "Below threshold", excerpt "An evening walk through the city center…".
A slim muted note below: "Select a candidate to inspect the text."
RIGHT PANEL, titled "Compare with selected", filename "river-weekend-041.txt", a small pill "Estimated Jaccard 0.94". Show a clean document comparison view using inline replacement marks, NOT an algorithm visualization. Small legend "Removed" in gentle amber and "Added" in soft green. Show the matched original document text with exact changed words: amber strikethrough "Saturday" followed by green "Sunday"; amber strikethrough "red bridge" followed by green "old bridge"; amber strikethrough "tea" followed by green "coffee". All other text is neutral and the same as the incoming document above. Make only these few replacement spans colored so the reader immediately sees a lightly edited copy. Readable typography and generous line height. Subtle bottom note: "Text differences are highlighted by the app."
5. Bottom footer, low visual emphasis: "Review candidates before merging or removing content." At the far right "Illustrative scores · Concept data".
Constraints: this is a safe read-only REVIEW interface, no automatic delete/merge action, no fake measured latency. Scores explicitly estimated Jaccard, never probability or confidence percentages. The selected score is 0.94 everywhere. Threshold 0.85 means exactly two of the three displayed retrieved candidates are above threshold. Preserve these consistencies. Absolutely NO hash arrays, random permutations, sorting demonstrations, LSH bucket diagrams, vector scatter plots, Embedding mode tabs, model dropdowns, clustering tabs or formula panels. The core visual story is incoming text → matching documents → inspect differences, expressed through working-looking UI panels, not a diagram. No giant hero, no sidebar navigation, no decorative 3D graphics. All UI text in English, sharp and legible. One cohesive full desktop screen.
