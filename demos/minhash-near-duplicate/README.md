# MinHash + LSH Near-Duplicate Detection

This demo finds copied and lightly edited documents with Milvus 3.0's built-in **MinHash
Function** and the **MINHASH_LSH** index. You paste (or pick a preset for) a document, Milvus
computes its MinHash signature and retrieves the most similar stored documents by **estimated
Jaccard similarity**, and the app renders a word-level diff so a human can inspect what changed.
No embedding model is involved.

```text
Browser /
  -> unified FastAPI static+API server on 127.0.0.1:48050
  -> Milvus 3.0.0 GA on 127.0.0.1:49530
  -> FunctionType.MINHASH over VARCHAR content
  -> MINHASH_LSH index + MHJACCARD metric + Jaccard refinement
  -> ranked candidates (1 - distance) and an app-side diff view
```

## Capability contract

- **Schema.** `doc_id` (VARCHAR primary key), `title` (VARCHAR), `content`
  (VARCHAR, `enable_analyzer=True`), and `minhash_signature` (`BINARY_VECTOR`, dim `8192`).
- **Function.** `FunctionType.MINHASH` with `num_hashes=256` (dim = 32 × 256 = 8192),
  `shingle_size=1`, word-level tokenization with the default `standard` analyzer. The signature
  is generated by Milvus at insert and query time; the demo never computes it itself.
  `shingle_size=1` is verified against the checked-in short texts: a two-word light edit keeps
  exact Jaccard near the `0.85` threshold (~0.85), whereas a 3-shingle drops the same edit to
  ~0.70 and would mislabel it as non-duplicate.
- **Index.** `MINHASH_LSH` / `MHJACCARD` with `mh_element_bit_width=32` and `with_raw_data=True`.
- **Search.** `mh_search_with_jaccard=True` with `refine_k=10`. Milvus's `MHJACCARD`
  metric returns the estimated Jaccard similarity directly in its `distance` field
  (larger is more similar; identical signatures score `1.0`), so the app reports that
  value verbatim as `estimated_jaccard` and keeps the raw field as `raw_distance`. It
  never applies a `1 - distance` transform, which would invert the scale. This was
  verified against the real Milvus 3.0.0 GA endpoint: an exact copy scores `1.0`, a
  two-word light edit about `0.86`, and unrelated text about `0.08`–`0.13`. The default
  threshold is `0.85`.

The collection is `milvus3_demos_minhash_near_duplicate`; its index is
`milvus3_demos_minhash_signature`.

## Fixed synthetic dataset contract

The tracked production dataset is
[`data/original-short-stories-r1`](data/original-short-stories-r1). It contains 36 original,
fictional short texts authored by the milvus3-demos project, organized into clusters that cover
every variant the concept requires:

| Variant | Meaning |
| --- | --- |
| `original` | The base fictional text for a cluster. |
| `exact-copy` | An exact copy of the cluster original. |
| `light-edits` | A few words changed against the original (near-duplicate). |
| `paragraph-removed` | A paragraph removed from the original (partial overlap). |
| `paragraph-added` | A new paragraph inserted into the original (partial overlap). |
| `same-theme` | Different wording on the same theme, no copied sentences. |
| `unrelated` | Unrelated content used as a below-threshold contrast. |

`documents.json` holds the documents, `presets.json` holds three preset queries
(light edits, paragraph added, exact copy), and `manifest.json` records the counts and variant
meanings. All text is dedicated to the public domain under CC0 1.0
(`licenses/LICENSE.txt`); see `NOTICE.md` and `LICENSE-CONFLICT.md`.

Validate the tracked bytes and dataset contract offline:

```bash
make minhash-near-duplicate-data-check
```

## API

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/healthz/live` | GET | Liveness. |
| `/healthz/ready` | GET | Readiness: prepared collection on Milvus 3.0.0. |
| `/api/v1/status` | GET | Dataset, presets, and Milvus audit. |
| `/api/v1/prepare` | POST | Create and load the collection from scratch. |
| `/api/v1/search` | POST | Near-duplicate search. Body: `query`, `threshold`, `limit`. |
| `/api/v1/cleanup` | POST | Drop only the exact demo collection. |

`/api/v1/search` returns ranked candidates with `estimated_jaccard`, `above_threshold`, and a
`diffs` array whose segments are `equal`, `removed`, or `added`. The diff is an application-side
reading aid, not a Milvus return value, and it compares the retrieved (existing) document against
the incoming text.

## Score semantics and honest limits

- Scores are **estimated Jaccard similarity** between MinHash signatures, never probabilities or
  model confidence.
- `MINHASH_LSH` is approximate and may miss near-duplicates; an empty or low count never proves
  that no duplicate exists. The response `semantics` field states this explicitly.
- A high similarity does not mean content is safe to delete; numbers, times, and negations still
  need human judgment. The UI is read-only review — there is no automatic merge or delete.
